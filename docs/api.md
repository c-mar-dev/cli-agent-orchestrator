# CLI Agent Orchestrator API

Base URL: `http://localhost:9889` (default)

Provider values accepted across API/flows:
- `q_cli`
- `claude_code`
- `kiro_cli`
- `codex`

`terminal_id` path params use the 8-character ID format generated by CAO (example: `a1b2c3d4`).

## Health

### `GET /health`
Returns service liveness.

## Diagnostics

### `GET /diagnostics/inbox/telemetry`
Returns inbox delivery telemetry plus DB idempotency/requeue counters.

### `GET /diagnostics/jsonl/gates`
Returns current JSONL migration gate evaluation payload.

### `POST /diagnostics/jsonl/reset`
Query params:
- `reset_parser` (bool, default `true`)

Resets JSONL canary telemetry.

## Sessions

### `POST /sessions`
Creates a new tmux session with exactly one terminal.

Query params:
- `agent_profile` (required)
- `provider` (default is runtime-configured `DEFAULT_PROVIDER`)
- `session_name` (optional)
- `working_directory` (optional)

Response: terminal object (`201 Created`).

### `GET /sessions`
Lists sessions.

### `GET /sessions/{session_name}`
Returns one session and its terminals.

### `DELETE /sessions/{session_name}`
Deletes session and terminal state.

## Terminals

### `POST /sessions/{session_name}/terminals`
Adds a terminal to an existing session.

Query params:
- `agent_profile` (required)
- `provider` (default runtime provider)
- `working_directory` (optional)

### `GET /sessions/{session_name}/terminals`
Lists terminal metadata for the session.

### `GET /terminals/{terminal_id}`
Returns terminal state.

### `GET /terminals/{terminal_id}/working-directory`
Returns current pane working directory.

### `POST /terminals/{terminal_id}/input`
Query params:
- `message` (required)

Sends input into the terminal.

### `GET /terminals/{terminal_id}/output`
Query params:
- `mode`: `full` or `last` (default `full`)

### `POST /terminals/{terminal_id}/exit`
Sends provider-specific exit command.

### `DELETE /terminals/{terminal_id}`
Deletes terminal metadata/provider state and resolves pending approvals with reason `terminal-deleted`.

## Inbox

### `POST /terminals/{receiver_id}/inbox/messages`
Creates (or resolves) an idempotent inbox message and triggers immediate delivery attempt.

Query params:
- `sender_id` (required)
- `message` (required)
- `idempotency_key` (optional; default derived from sender/receiver/message hash)
- `max_attempts` (optional, `1..100`)
- `requeue_terminal_state` (optional bool, default `false`)

Idempotency contract:
- Key uniqueness is `(receiver_id, idempotency_key)`.
- Existing `pending`/`retrying`/`delivered` row: returns canonical row unchanged.
- Existing terminal row (`dead_letter` or `failed`):
  - `requeue_terminal_state=true`: canonical row is reset to `pending`, retry metadata is reset.
  - `requeue_terminal_state=false`: canonical row is returned unchanged.

Inbox statuses:
- `pending`
- `retrying`
- `delivered`
- `failed`
- `dead_letter`

Common transitions:
- `pending -> delivered`
- `pending -> retrying -> delivered`
- `pending/retrying -> dead_letter` (attempt budget exhausted)
- `dead_letter/failed -> pending` when explicit requeue is enabled for same idempotency key

### `GET /terminals/{terminal_id}/inbox/messages`
Query params:
- `limit` (default `10`, max `100`)
- `status` (optional): one of `pending`, `retrying`, `delivered`, `failed`, `dead_letter`

Returns oldest-first inbox rows.

## Approvals

### `GET /terminals/{terminal_id}/approvals`
Query params:
- `limit` (default `20`, max `200`)
- `status` (optional): `pending`, `acknowledged`, `resolved`

Returns approval queue rows for the terminal.

### `POST /terminals/{terminal_id}/approvals/{approval_id}/ack`
Body:
- `sender_id` (required)
- `response_message` (optional, required when `auto_send=true`)
- `auto_send` (bool, default `true`)

Behavior:
- Marks pending approval acknowledged.
- If `auto_send=true`, sends `response_message` to terminal and resolves approval.

## Error Shape

All failures return:

```json
{
  "detail": "Error message"
}
```

Common status codes: `200`, `201`, `400`, `404`, `422`, `500`.
